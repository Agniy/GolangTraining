# 29 — пакет context

Пакет **`context`** (Go 1.7, 2016) — стандартный способ передавать через
горутины и вызовы функций:

- **сигнал отмены** и **дедлайн** (чтобы вовремя останавливать работу);
- **значения, привязанные к запросу** (request ID, пользователь, трассировка).

Это фундамент любого сетевого/конкурентного Go-кода: HTTP-серверы, gRPC,
запросы к БД — все принимают `context.Context` первым аргументом.

## Запуск

Раздел — это один модуль (`go.mod`). Каждый пример — отдельный пакет `main`:

```sh
cd 29_context
go run ./01_background-todo
go run ./02_with-cancel
# ...и так далее
```

## Главные правила

1. **Контекст — первый аргумент:** `func Do(ctx context.Context, ...) error`.
   Не храните контекст в структурах.
2. **Всегда вызывайте `cancel`** (обычно `defer cancel()`), даже если контекст
   уже завершился по таймауту — иначе утекают ресурсы. `go vet` это проверяет.
3. **Слушайте `ctx.Done()`** в долгих операциях и возвращайте `ctx.Err()`.
4. **`WithValue` — только для сквозных данных запроса**, не для обязательных
   параметров. Ключи — своего неэкспортируемого типа, не `string`/`int`.

## Дерево контекстов

```
Background()/TODO()                 // пустой корень
   └── WithCancel / WithTimeout / WithDeadline / WithValue   // производные
          └── ещё производные ...
```

Отмена родителя автоматически отменяет всех потомков. `ctx.Err()` объясняет
причину: `context.Canceled` или `context.DeadlineExceeded`.

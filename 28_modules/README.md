# 28 — Go Modules

Раздел про **систему модулей** — официальный способ управления зависимостями
и версиями в Go (Go 1.11, 2018; воркспейсы — Go 1.18, 2022).

Это первый раздел курса, написанный в модульном стиле. Папки 01–27 используют
старый подход GOPATH; здесь каждый пример — **самостоятельный модуль** со своим
`go.mod`, поэтому старая структура не затрагивается.

## Краткая шпаргалка

```sh
go mod init example.com/proj   # создать модуль
go mod tidy                    # синхронизировать зависимости
go get pkg@v1.2.3              # добавить/обновить зависимость
go list -m all                 # все модули сборки
go work init ./a ./b           # создать воркспейс из модулей a и b
```

## Что такое go.mod / go.sum

- **`go.mod`** — имя модуля, версия Go, список зависимостей. Коммитится.
- **`go.sum`** — контрольные суммы зависимостей для воспроизводимости. Коммитится.
- **`go.work`** — локальный воркспейс из нескольких модулей. Обычно в `.gitignore`.

## Ключевая историческая справка

До Go 1.11 весь код жил в `$GOPATH/src`, версии зависимостей не фиксировались
(использовался последний коммит из `go get`). Модули сделали проекты
размещаемыми где угодно и ввели воспроизводимые, версионируемые сборки.

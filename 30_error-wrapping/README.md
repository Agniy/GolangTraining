# 30 — обёртка ошибок (error wrapping)

Расширяет раздел [23_error-handling](../23_error-handling). Показывает
механизм **обёртки ошибок**, появившийся в Go 1.13 (2019) и дополненный
`errors.Join` в Go 1.20 (2023).

## Зачем

Раньше при добавлении контекста к ошибке исходная ошибка терялась:

```go
return fmt.Errorf("loadConfig: %v", err) // err стал просто строкой
```

Теперь ошибку можно **обернуть**, сохранив исходную внутри, и потом надёжно
её разобрать — независимо от глубины обёрток.

## Шпаргалка

| Инструмент | Вопрос, на который отвечает |
|---|---|
| `fmt.Errorf("...: %w", err)` | как обернуть ошибку, сохранив исходную |
| `errors.Is(err, target)` | «это та самая ошибка?» (сравнение по значению) |
| `errors.As(err, &target)` | «есть ли ошибка такого типа?» (+ достать её) |
| `errors.Unwrap(err)` | снять один слой обёртки |
| `errors.Join(e1, e2, ...)` | объединить несколько ошибок в одну |

## Правила

1. Оборачивайте `%w`, когда вызывающему важно опознать первопричину;
   используйте `%v`, если хотите намеренно «спрятать» детали реализации.
2. Сравнивайте sentinel-ошибки через `errors.Is`, а **не** `==`.
3. Доставайте типизированные ошибки через `errors.As`, а **не** type assertion.
4. Свой тип ошибки делайте частью цепочки, добавив метод `Unwrap() error`.
